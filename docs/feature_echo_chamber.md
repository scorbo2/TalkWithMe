# Echo chamber

This document describes an addition to the TalkWithMe app.
The goal is to add a boolean config option to each chat room: "echo chamber".
The default value is `false`, to match the current behaviour.
If `true`, the feature described in this document is activated for that chat room.

## Current state

The current chat flow is perfectly standard: the user types or speaks a prompt, and
one of the configured AI personas answers. The persona's response is generated by the
configured LLM, using the system prompt configured for the persona in question.

## Desired state

If "echo chamber" is activated for the current chat room, the system prompt for all
personas present is suppressed, and replaced with a much simpler one:

```
You are in "echo mode". Respond to any user prompt by simply repeating the user prompt verbatim.

Example: 
  - the user submits "hello there, how are you?"
  - whichever persona answers should respond with "hello there, how are you?"
```

Persona selection (the "Who should answer?" chooser) is unaffected by this change:

- if "Selected persona" is selected, the prompt should be answered by the selected persona.
- if "Surprise me" is selected, the prompt should be answered by any randomly selected persona in the current chat room.
- if there is only one AI persona in the chat room, that persona should answer.
- if there are no AI personas in the chat room, the default "No one is here" message should be displayed as before.
- if "LLM decides" is selected, the usual LLM selection process can be used.

The `persona_name_mentions` override should still behave the same way. That is, if the user mentions a specific 
persona by name, and `persona_name_mentions` is enabled in configuration, that persona should answer, regardless
of the state of the "Who should answer?" chooser. This logic is the same as before.

The only difference is the system prompt that we provide to the LLM for the selected persona, unless the
suggested optimization is implemented (see "Suggested optimization").

### UI Changes

A new checkbox should be added to the sidebar underneath the chat room dropdown.

- Label: "Echo chamber"
- Initial state: taken from the `chatrooms.yaml` if present. Defaults to unchecked if not present in config.

Checking or unchecking this checkbox should immediately update the configuration for the current chat room (see Persistence section).

Switching chat rooms via the Chat Room dropdown should update the checkbox according to the currently selected chat room.

There are no other UI changes. There is no need to modify the Chat Rooms creation/edit dialog. When a new chat room
is created, its "Echo chamber" setting will default to off. It must be explicitly enabled in the UI in the left panel.

### Persistence

A new per-chatroom boolean configuration option `echo_chamber` should be persisted in `chatrooms.yaml`. It is not
an error if this property is not present when reading this file. The option should default to false, to match
the previous behaviour.

### API changes

The front end needs a way to immediately persist changes to the "Echo chamber" configuration property of any given chat room.
The handler should write out `chatrooms.yaml` with the new value.

### Suggested optimization

A round trip to the LLM just to return the user prompt will use tokens unnecessarily. If "echo chamber" is enabled, we could
skip `stream_chat()` call entirely and just directly yield the user message as the response. Something like this:

```
if echo_enabled:
    full_text = req.message
    yield f'data: {json.dumps({"type": "start", "persona": persona_name, "user_message_id": user_message_id})}\n\n'
    yield f'data: {json.dumps({"type": "token", "persona": persona_name, "token": full_text})}\n\n'
    # ... emit done/complete
else:
    # existing LLM streaming path
```
